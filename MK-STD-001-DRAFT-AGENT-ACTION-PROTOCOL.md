# MK-STD-001 — Agent Action Protocol Standard, v0.5 (draft proposal — LIVE-FIRE AMENDED)

**Draft for comment, not a standard in force · November 2026 · five review rounds absorbed: four adversarial board rounds (STD1-01..STD1-20) + one live-fire round against verified threats (SDT-01 CVE-2026-124194 / SDT-02 FBI FLASH ARTEX; findings SDT-01-01..03, SDT-02-01..03)**
**Position document.** No conformance program; no certification offered or implied; no conformance claims may be made against this document. Companion to MK-STD-002 — Sovereign Agent Infrastructure Standard (deployment layer). Precedence: MK-STD-001 governs action-level gates; MK-STD-002 governs deployment-level sovereignty claims. **§0 Scope — what this protocol governs, and what it defers (SDT-01-01).** This protocol governs **agentic proposals** — actions where a component formulates intent and proposes a consequential operation. **It does not govern non-agent monolithic execution.** A file parser that follows a format into an OS-level network request does not read authorization files, form intent, or propose actions — and application-layer authorization cannot govern ambient parser execution. **For non-agent consequential components, enforcement defers to OS-level mediation** — eBPF, LSM hooks, network namespace policy, or a sidecar proxy — as the deployment layer's datapath specifies (MK-STD-002 §4). The standard says this at its boundary so no reader expects the agent layer to catch what only the OS layer can see.

**Preamble — the discipline, scoped honestly.** ATLS — one of the most widely adopted procedural protocols in medicine, taught in over 80 countries — standardized the first ten minutes of trauma care because those minutes decide everything that follows. This document borrows the discipline, not the specific protocol: a fixed-order survey, observable criteria per gate, drilled and audited. Offered as a draft for comment, not a standard in force.

**Section 1 — Stop-work clause (the spine — an invariant).** Human-held, single signal, logged independently. The halt blocks pending actions and new authorizations until a named human re-authorizes; "pending" = queued + in-flight + any authorization issued but not yet consumed. Committed side effects at targets the action layer does not control are reconciled by observation, not reversal; unobservable targets record MISSING and block re-authorization. Reconciliation by an independent observer, recorded MATCH / MISMATCH / MISSING / UNKNOWN; observer selection per the registry rule, with the Nominally Gated residual declared. Tested as an invariant: auditor-selected sampling or construction. Continuity: succession, availability, dead-man.

**Section 1.5 — Machine-speed halt (SDT-02-02).** A 30-day review bound is governance; it is not a defense against a three-hour adversary. **The spine must support automated velocity and anomaly triggers** — sudden bursts of authority requests, scope-expansion patterns, egress-rate anomalies — **that halt execution pending human re-authorization.** Real-time halt is checkable by construction: the trigger is deterministic, its threshold is declared, and the halt state is observable by the independent observer. The 30-day bound governs post-halt review; the trigger itself owes nothing to the review cycle.

**Section 2 — Primary survey (six gates; failure halts).** Intent identified → authority confirmed → scope bounded → execution logged → evidence sealed → review possible. **Gate 2 — verifier-visible authority, with a closed root and no ambient authority (SDT-01-02; SDT-02-03).** Authority is a signed, scoped, time-bound lease issued by a party the agent does not control. **Declared authorization does not satisfy this gate — a file in context named authorization.md is data, not authority.** **No ambient authority:** a consequential operation must not use credentials implicitly held by the execution environment; the lease explicitly binds the credential to the authorized scope. **Model discretion is not a deterministic gate:** if a deployment relies on an LLM deciding whether an action proceeds, it fails Gate 2 by definition — the gate is a policy engine evaluating signed claims, not a model evaluating prose. The signature is verified against a trusted key not received through the input stream; bootstrap anchored (hardware root, out-of-band-pinned registry, or TOFU only with out-of-band human verification); where the deployment layer's authority infrastructure provides the root, Gate 2 uses it; where absent, the action fails closed. **Enforcement locus (SDT-01-03):** the explicit capability request is mediated at a **mandatory mediation point outside the application** — network namespace, LSM hook, or sidecar proxy — never inside a vulnerable parser. Failure at any gate halts the survey; the failure is a non-passing M&M entry.

**Section 3 — Scenario cards (a floor with a growth mechanism).** Eight mandatory classes, each naming its catching gate; four novel scenarios per certification cycle, "novel" defined structurally; card templates maintained in the scenario registry, cited by digest; M&M closure = card inclusion.

**Section 4 — Certification layers, with gate strengths in the claim.** Individual operator certification by a certifier independent of the vendor; where none exists, declared residual. Independently Gated / Nominally Gated, in the claim's first line and machine-readable field; omission is an incomplete claim.

**Section 5 — M&M review.** Triggers, 30-day bound (governing post-halt review only — real-time response is Section 1.5), schematized artifact, independent version-bump authority, closure = card inclusion.

**Section 6 — The bridge.** MK-STD-001 requires verifier-visible authority; MK-STD-002 specifies the verification method. The authority gate requires independence; the Accommodated-instrument path satisfies Nominally Gated — declared in the claim.

**Standing boundary — including the opt-in scope, stated (SDT-02-01).** No implementation claimed, no product, no conformance claims against this draft. **Scope, stated plainly: these standards govern the enforcement mechanisms of compliant deployments. They do not prevent external adversaries from attempting actions; they ensure that, within a compliant deployment, consequential actions cannot execute without passing the gate.** A draft is a door, not a wall.
